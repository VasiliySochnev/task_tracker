## EndPoints(Основные)
- "tasks/summary/<int:order_id>/"(API для получения активных задач по конкретному заказу.
    Используется в интерфейсе сотрудника для просмотра текущих задач.)
- "least_busy_employees/"(Возвращает наименее загруженных сотрудников по должностям:
    комплектовщики, грузчики, приемщики, логисты, курьеры.
    Учитывает отдел и зону отгрузки, если указаны.)
- "tasks/important/"(API для получения оставшихся ключевых статусов заказа.
    Возвращает список статусов, начиная с текущего и до предпоследнего.)
- "order_detail/<int:order_id>/"(Отображение детальной информации о заказе: список задач, история статусов и сотрудников.
    Также обрабатывает POST-запросы для завершения текущей задачи и создания следующей.)
- "busy-employees/"(API для отображения сотрудников, выполняющих задачи.)
- "swagger/"  |  "redoc/" (Для отображения документации приложения.)


## Функциональность
Данный проект разрабатывается для работы на складе для строительного магазина,
он подразумевает собой наличие терминалов для сотрудников склада для отслеживания статусов
сборки товаров для заказов клиентов, как показано выше склад имеет 6 отделов для различных товаров,
3 зоны отгрузки, персонал для сборки товаров и логистической линии, персонал для работы с товарами и клиентами.
Вся цепочка сборки заказа и отправки клиенту собрана предварительно, так же как и персонал в организации.

## Бизнес-ценность

1. Ключевые бизнес-выгоды:
- Повышение скорости обработки заказов
- Автоматическое назначение задач сотрудникам сокращает время на сборку и уменьшает простои.

2. Снижение ошибок при комплектации.
- Сотрудники получают четкие инструкции, какие товары и в каком количестве собрать — это 
снижает количество возвратов и недостач.

3. Оптимизация работы персонала.
- Система равномерно распределяет нагрузку между сотрудниками склада и логистами, повышая производительность.

4. Прозрачность и контроль.
- Руководство в реальном времени видит статус заказов, прогресс по задачам, задержки и узкие места в логистической цепочке.

5. Повышение удовлетворенности клиентов.
- Быстрая и точная доставка, а также возможность отслеживания заказа — повышают доверие и лояльность клиентов.

6. Масштабируемость.
- Система готова к расширению — можно легко добавлять новых сотрудников, товары и зоны доставки без изменения бизнес-процессов.

## Установка

Для запуска проекта выполните следующие шаги:

1. Клонируйте репозиторий:
   
git clone https://github.com/VasiliySochnev/task_tracker/tree/feature

2. Установите зависимости:
   
pip install --no-cache-dir -r requirements.txt

3. Создайте файл .env по шаблону env.sample и добавьте свои настройки
   (для запуска локально HOST=localhost, для контейнера HOST=db)

4. С помощью команды "python manage.py csu" создайте администратора.
5. Выгрузите фикстуры из директории fixtures:
python manage.py loaddata name_fixtures
   (очередность выгрузки)
- users.json
- departments.json
- shipping_zones.json
- employees.json
- products.json
6. Запустите приложение:
- python manage.py runserver

7. Запустите терминал redis для работы задачи

8. Запустите celery:
- celery -A config worker --loglevel=info --pool=solo

9. Зайдите на администраторскую панель в браузере http://127.0.0.1:8000/admin/
- email: admin@mail.ru
- password: admin
10. Создайте одного клиента и один адрес.
11. Создайте заказ с товарами и нажмите SAVE.
12. Откройте страницу с адресом, где <int:order_id> это номер заказа: 
- http://127.0.0.1:8000/admin/tracker/order_detail/<int:order_id>/

## Использование
После создания заказа Celery уже запустила задачу, здесь вашему вниманию будет показана
очередность создания задач для сотрудников, которые будут выполнять работы для заказа с товарами,
который уедет к клиенту. Тут приложение предлагает просимулировать работу каждого сотрудника, для 
этого нужно нажимать кнопку завершить, после того как сотрудник закончил свою задачу - создается 
следующая для очередности выполнения работы и так до самого конца - до доставки, так как 
работа сотрудников подразумевает разные задачи в разных местах (будь то отдел или зона отгрузки),
здесь настроена следующая логика - пока весь товар для заказа из разных отделов не прибудет в свою
зону отгрузки, задача приемщику не назначается.


## Контейнеризация и настройка.

В проекте создан и настроен Dockerfile для сборки, так же еще docker-compose.yaml для запуска.
1. Для сборки и запуска выполните команду:
- docker-compose up --build
2. После сборки выполните команду для просмотра запущенных контейнеров:
- docker ps 
3. Выберите id контейнера с названием образа task_tracker-web и скопируйте в команду для выполнения:
- docker exec -it id sh 
4. Теперь у вас должен открыться терминал запущенного приложения развернутого на Docker,
командой ls можно проверить главная ли директория сейчас открыта, 
здесь так же можно применить миграции и выгрузки фикстур для работы с приложением.
